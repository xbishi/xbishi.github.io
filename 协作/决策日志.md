# 决策日志 — bs-portfolio

记录所有结构性决策（技术选型、架构、范围变更、依赖引入）。
**先记后做**：重大改动没记录就动手，视为违反公约。

## D-001 · 数据驱动架构：一个项目 = 一个 Markdown 文件
- 日期：2026-11-19
- 决策人：智能体建议（负责人未拍板，按默认执行，可推翻）
- 背景：项目分散在多个工作空间，网站必须让「加项目」成本极低，否则必然烂尾
- 决定：项目数据存 `src/content/projects/*.md`（frontmatter 元数据 + 正文详情），Astro content collections 生成页面
- 备选：单一大 JSON（字段多了难维护）；直接扫描各工作空间 PROJECT.md（跨盘耦合，首期不做，M3 后可加同步脚本）
- 影响：全站架构；与工作空间「归档」规则对齐（archived 状态）

## D-002 · 首期以对外展示为主（待负责人拍板）
- 日期：2026-11-19
- 决策人：智能体建议，**负责人未回答，属默认方向**
- 背景：网站受众有「对外作品集」vs「自用导航」两派，设计方向不同
- 决定：首期对外展示优先（体面的卡片/详情页）；数据同源，后补自用导航视图成本低
- 备选：自用导航优先（被否：书签可凑合替代，对外展示无替代品）；两者同时做（首期工作量翻倍）
- 影响：首页布局、关于页；负责人若推翻则重排首页信息优先级

## D-003 · 技术栈 Astro + Tailwind，部署 GitHub Pages（待负责人拍板）
- 日期：2026-11-19
- 决策人：智能体建议，**负责人未回答，属默认方向**
- 背景：纯静态展示站，要求构建快、维护简单、零服务器成本
- 决定：Astro 5 + Tailwind CSS 4 + pnpm，GitHub Actions 自动部署 GitHub Pages
- 备选：Next.js（互动上限高但对展示站偏重）；纯 HTML 单页（项目 >10 个后维护痛苦）；Vercel（国内访问不稳且不必引入）；国内服务器（需备案，首期不碰）
- 影响：全部开发与部署流程；负责人若推翻影响 M1 排期约 +1 天

## D-004 · 部署通道：Actions → gh-pages 分支手动部署
- 日期：2026-11-19
- 决策人：智能体决定（技术阻塞下的等价替代，未改变部署结果）
- 背景：gh OAuth token 缺 `workflow` scope，包含 `.github/workflows/` 的提交被远端拒绝
- 决定：main 分支暂缓 workflow 文件（本地保留）；构建产物手动推 `gh-pages` 分支部署（dist 内独立 git init + push -f）。仓库 `xbishi/xbishi.github.io`（用户主页根站，无 base 路径）
- 备选：等负责人 `gh auth refresh -s workflow` 后切回 Actions（推荐，命令已在 README）
- 影响：部署流程（见 README「怎么更新线上」）；首次 Pages 曾被 Jekyll 渲染 main README 干扰，已用 `pages/builds` 手动重建解决——**以后每次更新 gh-pages 后若内容未变，触发 `gh api -X POST repos/xbishi/xbishi.github.io/pages/builds`**

## D-006 · V2 视觉改版：霓虹终端+微光晕方向
- 日期：2026-11-19
- 决策人：负责人提出「太丑、要简洁+体验+氛围感」后未在选项中拍板，智能体按推荐方向执行（可推翻换皮）
- 背景：调研 astro-theme-cactus（1.8k★ 活跃）/ astro-paper / Brittany Chiang 范式 / Linear 风格后给出三方向：极简瑞士、霓虹终端、光晕玻璃
- 决定：**霓虹终端+微光晕融合**——深蓝黑底 #05070d + 薄荷青霓虹 #3ce6b0、等宽字体体系、终端 kicker（$ whoami / // featured）、渐变标题、玻璃卡 hover 霓虹描边、三层氛围背景（光晕/网格/噪点）、滚动淡入、暗色滚动条。设计 tokens 全部以 CSS 变量暴露在 :root（@theme），改色=改 3 个变量
- 备选：极简瑞士印刷风（风险：平庸显得简陋）；纯光晕玻璃（代码量最大）；换方向只需改 global.css+布局类名，数据层零改动
- 影响：全部视觉文件（global.css/Base/index/ProjectCard/详情页）；截图存 docs/截图/V2-*.png
