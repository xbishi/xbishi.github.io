## D-001 · 数据驱动架构：一个项目 = 一个 Markdown 文件
- 日期：2026-11-19
- 决策人：智能体建议（负责人未拍板，按默认执行，可推翻）
- 背景：项目分散在多个工作空间，网站必须让「加项目」成本极低，否则必然烂尾
- 决定：项目数据存 `src/content/projects/*.md`（frontmatter 元数据 + 正文详情），Astro content collections 生成页面
- 备选：单一大 JSON（字段多了难维护）；直接扫描各工作空间 PROJECT.md（跨盘耦合，首期不做，M3 后可加同步脚本）
- 影响：全站架构；与工作空间「归档」规则对齐（archived 状态）

## D-002 · 首期以对外展示为主（待负责人拍板）
- 日期：2026-11-19
- 决策人：智能体建议，**负责人未回答，属默认方向**
- 背景：网站受众有「对外作品集」vs「自用导航」两派，设计方向不同
- 决定：首期对外展示优先（体面的卡片/详情页）；数据同源，后补自用导航视图成本低
- 备选：自用导航优先（被否：书签可凑合替代，对外展示无替代品）；两者同时做（首期工作量翻倍）
- 影响：首页布局、关于页；负责人若推翻则重排首页信息优先级

## D-003 · 技术栈 Astro + Tailwind，部署 GitHub Pages（待负责人拍板）
- 日期：2026-11-19
- 决策人：智能体建议，**负责人未回答，属默认方向**
- 背景：纯静态展示站，要求构建快、维护简单、零服务器成本
- 决定：Astro 5 + Tailwind CSS 4 + pnpm，GitHub Actions 自动部署 GitHub Pages
- 备选：Next.js（互动上限高但对展示站偏重）；纯 HTML 单页（项目 >10 个后维护痛苦）；Vercel（国内访问不稳且不必引入）；国内服务器（需备案，首期不碰）
- 影响：全部开发与部署流程；负责人若推翻影响 M1 排期约 +1 天
