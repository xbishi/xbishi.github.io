# 部署到自己的服务器 — 操作指南

产物是**纯静态文件**（`dist/`），任何能跑 nginx 的服务器都能托管。三条路任选其一：

---

## 路线 A：SSH 直连（最快，推荐）

给 AI 这些信息即可由 AI 代跑 `server/deploy.sh`：
- 服务器 IP、SSH 端口、用户名
- 认证方式（密码 / 已配好的密钥）

自己手动跑（Git Bash 里）：
```bash
cd H:/BS一人公司/项目/bs-portfolio
./server/deploy.sh root@你的IP 22
```

服务器侧一次性准备：
```bash
sudo mkdir -p /var/www/bs-portfolio
sudo chown $USER /var/www/bs-portfolio
# 把 server/nginx-bs-portfolio.conf.example 复制为
# /etc/nginx/sites-available/bs-portfolio，改 server_name 后：
sudo ln -s /etc/nginx/sites-available/bs-portfolio /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

## 路线 B：宝塔/1Panel 面板

1. 面板 → 网站 → 添加站点：域名/IP + 纯静态
2. 上传 `release/bs-portfolio-dist.zip` 到站点根目录并解压
3. 伪静态/默认文档确认包含 `index.html`
4. （可选）在面板申请 Let's Encrypt 证书开 HTTPS

## 路线 C：域名与 HTTPS（部署后做）

1. DNS：给域名加一条 A 记录指到服务器 IP（如 `me.bishi.tech`）
2. HTTPS：
```bash
sudo apt install certbot python3-certbot-nginx   # Debian/Ubuntu
sudo certbot --nginx -d me.bishi.tech            # 自动改 nginx 配置并续期
```

---

## 更新站点

| 方式 | 命令 |
|---|---|
| AI 代跑 | 把改动告诉 AI，跑 `./server/deploy.sh ...` |
| 手动 | `pnpm build` 后把 `dist/` 内容重新上传覆盖 |
| 面板 | 重新上传 zip 解压覆盖 |

## 已知坑
- `dist/` 里的 `projects/*/index.html` 是目录结构，rsync/解压都要保留目录层级
- nginx `try_files $uri $uri/ =404` 不能写成 SPA fallback（不需要）
- 更新后若浏览器有缓存：HTML 已设 no-cache，强制刷新（Ctrl+F5）即可
